# Internal user/employee linkage and form-submit UX — Test Plan

**Plan status:** Detailed
**Overall test status:** Mixed — focused cases Implemented / Not Run; remaining cases Planned / Not Run
**Related features:** `FND-02`, `MST-01`, and shared application form UX

This plan covers the bidirectional `INTERNAL` membership ↔ Employee invariant and representative submit-result/reset behavior. It deliberately samples each form family instead of repeating the same component assertion on every screen. No test in this batch was executed while authoring.

## Deterministic fixtures

- Real frontend/backend and the shared PostgreSQL test schema; no business API mocks, production data, or arbitrary sleeps.
- Two tenants with lookalike employee codes; Tenant A has an owner/access admin, a scoped master admin, one activated unlinked `INTERNAL` membership, one already-linked membership, and `CLIENT`, `VENDOR`, and `DRIVER` memberships. Tenant B mirrors the identifiers.
- Tenant A has an active legal-entity/region/branch tree and an unlinked active Employee whose normalized employee code and destination match the unlinked internal membership.
- Representative form families: Employee create/edit (master), indent create (operations), invoice create (finance), saved view (control tower), user profile/invitation (access), and tenant-user invitation/profile (platform).
- Every mutation uses a unique namespace and waits on the response plus persisted projection; failure cases compare canonical row/audit/outbox counts before and after.

## Critical risks

- A linkage command could create privilege implicitly from employee hierarchy rather than preserving the administrator-supplied role/action/scope intersection.
- Updating one projection could leave stale identity, employee, authorization-version, session, onboarding, audit, or outbox state.
- A global banner can make users repeat a committed mutation because its result is detached from the initiating form.
- Unconditional reset can destroy corrective input after failure or erase persisted edit values; stale success can appear beside a later form.
