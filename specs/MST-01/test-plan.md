## Scope and oracle

This plan covers the operable organization, employee, ownership, and geography master slice: the Masters landing/navigation, legal-entity/region/branch/team hierarchy, PIN-derived address selection, structured geofences, searchable references, employee reporting lines and home nodes, bulk operational assignments, hierarchy moves, impact-aware deactivation/reassignment, scoped authorization, audit, and reconciled master reports.

PostgreSQL state and the supported HTTP contracts are the authoritative oracle. Browser messages alone are not completion evidence. Tests use the locally deployed frontend/backend and central PostgreSQL service without request interception, mocked APIs, arbitrary sleeps, or production data. Financial ledger testing is not applicable to MST-01; report and audit reconciliation remain mandatory.

## Risks

1. Parent, manager, home-node, linked-membership, or assignment identifiers could be accepted from another tenant or outside the actor's scope.
2. Organization or employee-manager cycles could corrupt hierarchy traversal, scope inheritance, filters, reports, and alerts.
3. Deactivation could silently orphan active assignments, client locations, open work, or escalation routes.
4. A stale hierarchy move or reassignment could overwrite a concurrent administrator change.
5. Retried creates or commands could duplicate nodes, employees, assignments, audit rows, or outbox events.
6. Free-text city/state could disagree with the PIN reference, and a multi-locality PIN could silently select the wrong locality.
7. Unknown PIN and postal-service failures could lose entered data or partially persist a master record.
8. Raw JSON geofence entry, malformed polygons, invalid coordinates, or unsafe radius values could make location matching unusable.
9. Reference controls could reveal cross-tenant/out-of-scope records or submit stale/inactive choices.
10. Hierarchy-derived list, report, export, dashboard, and alert-recipient totals could disagree.
11. Sensitive employee email/mobile data could be exposed without explicit sensitive-field permission.
12. Migration/backfill could damage existing canonical masters or other projects in the shared PostgreSQL container.
13. Tree, map, reference search, impact confirmation, and bulk assignment interfaces could be inaccessible by keyboard or on mobile.

## Unit tests

- Put pure validation, hierarchy-cycle/closure, active-date, geofence, PIN-selection, and orphan-policy cases beside `@logistics/domain` code. Use table-driven before/at/after values and mutation-sensitive assertions.
- Node hierarchy compatibility must follow the approved spec. Tests must enumerate every allowed parent-child pair and reject every other pair; they must not merely check that `parentId` is a UUID.
- Geofence serialization must be canonical and deterministic so idempotency hashing is independent of UI field order. Polygon tests also reject a repeated closing vertex if the canonical contract closes it implicitly.

## Integration and migration tests

- Integration tests use actual PostgreSQL transactions. Concurrency uses explicit database barriers/advisory locks, not timing delays.
- Metadata-driven tenant isolation covers `organization_nodes`, `organization_closure`, `employees`, `operational_assignments`, feature report/projection relations, and any new address/geofence relation introduced by the implementation.
- Migration verification asserts composite tenant-qualified foreign keys, uniqueness, closure indexes, effective-date checks, geofence/address constraints, RLS classification, and preservation of existing canonical rows.
- Failure injection is test-only, authenticated where exposed, disabled in production, and records no false successful audit/outbox event.

## API/contract and idempotency tests

- All mutations validate session-derived tenant, CSRF/origin, action capability, resource scope, active referenced records, schema strictness, expected version, and idempotency key where retry is safe.
- Search endpoints normalize ordinary case/whitespace without treating `%`, `_`, quotes, or Unicode as SQL syntax. Ordering uses a stable tie-breaker.
- Detail, impact, report, and export payloads expose purpose-built fields. Foreign-known and unknown UUIDs have equivalent safe public contracts.
- Same-key retries assert one business row, closure update, assignment set, audit event, and outbox event. A different normalized payload under the key returns conflict.

## Authorization and tenant-isolation tests

- Test every MST-01 resource and command in both tenant directions and with scoped same-tenant actors. Scope authorization is evaluated at the target resource/service boundary, including parent, replacement employee, home node, linked membership, client and location references.
- A parent or replacement that is visible under one grant cannot be combined with a target allowed under an unrelated grant unless one complete assignment authorizes the operation.
- Read permission does not imply create/update/admin/export. Sensitive mobile/email permission is independently enforced in list, detail, report, export, audit snapshots, alerts and logs.

## Reconciliation and audit tests

- Organization report totals equal distinct canonical nodes under the exact state/scope filter. Closure joins must not multiply records by ancestor count.
- Ownership reports count each active client/location/open workflow once against its effective owner at the frozen time. Assignment start is inclusive and end is exclusive.
- Orphan alerts derive from canonical ownership and escalation state, deduplicate on replay, and close/reopen predictably when ownership changes.
- Create, hierarchy move, bulk assignment, reassignment/deactivation, transition and denial events carry actor, UTC timestamp, target, safe before/after data, reason, request/correlation ID, and impersonation context when present.

## Playwright journeys

### E2E-MST01-01 — Primary create and use

The Tenant A Owner opens a discoverable Masters landing page, enters a PIN-first address for a legal entity/branch, confirms derived locality/city/state, chooses IST, creates a polygon or point-radius geofence through the map control, and builds `LE-A > NORTH-A > BLR-A > TEAM-A`. The owner creates an employee using searchable Manager, Home organization node and optional Linked user controls, then bulk-assigns that employee to a queue/client. UI detail, supported APIs, hierarchy tree and report all show the same persisted records. Users never type a UUID, city/state, or JSON.

### E2E-MST01-02 — Validation with no partial mutation

From captured API/report counts, submit an invalid node/employee covering reversed dates, malformed mobile, invalid parent, unknown PIN and mode-incomplete geofence. The first invalid field receives focus and its error is associated/announced. No node, employee, closure edge, assignment, audit success, outbox event, report row or alert is added. Correct the values and prove one successful submission.

### E2E-MST01-03 — Tenant, scope and role isolation

North Admin creates and reads a North descendant but cannot discover or submit the South parent/employee references. Reader can view permitted records with sensitive data masked but cannot mutate/export. Client Viewer and anonymous actor are denied. Tenant B Owner attempts Tenant A known IDs through routes and direct APIs; results match unknown IDs and Tenant A data is absent from UI, search, report, export, audit and alert surfaces.

### E2E-MST01-04 — Postal and deactivation recovery

The owner proves unique-PIN auto-selection, explicit deterministic selection for an ambiguous PIN, unknown-PIN guidance, and one transient lookup failure followed by Retry while address lines remain. Next, the owner opens NORTH-MGR-A's impact view, sees exact affected categories/counts, and cannot use a plain disable that would orphan work. Selecting REPLACEMENT-A and entering a reason atomically reassigns active responsibilities and deactivates the old manager. ### E2E-MST01-05 — Reconciliation, accessibility and responsive behavior

## Accessibility and responsive checks

- Dates use labelled calendar controls; timezone defaults to `Asia/Kolkata`. Optional fields state “Optional” in visible/programmatic help.
- Search/select references expose loading, no-result, selected and inactive/stale states, work by keyboard, and never expose raw IDs as required input.
- The hierarchy uses semantic tree/treeitem levels and expanded state, or an equivalently accessible nested structure. Drag-only movement is insufficient; a keyboard-operable move form/action is required.
- Geofence has an accessible non-pointer path for coordinates/vertices and radius while preserving the structured map experience. Instructions and validation identify the active mode.
- Impact and reassignment confirmations name consequences and return focus. Loading, empty, forbidden, conflict and retry states are announced without focus loss.
- Desktop and mobile runs must not rely on horizontal scrolling for primary actions; tables may use a labelled responsive container with accessible headers.

## Failure injection and recovery

- Inject one postal lookup 503, one audit/outbox persistence failure, a stale expected-version conflict, and a concurrent hierarchy-move/reassignment race through non-production test controls or transaction barriers.
- Postal Retry repeats only the lookup and preserves non-secret address inputs; it cannot create a partial master or silently fall back to free-text city/state.
- Audit/outbox failure rolls back the business mutation. A same-key retry after recovery commits exactly once.
- Stale hierarchy/reassignment commands reload current data before user retry and never overwrite the winner. Closure and ownership remain internally consistent after either ordering.
- A report-projection/alert evaluator rerun reconciles idempotently from canonical rows without duplicate records or cross-tenant processing.
